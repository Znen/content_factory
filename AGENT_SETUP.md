# Задание агенту: развернуть Content Factory (fal.ai / Replicate) и подключить к Codex

Ты — агент, помогающий пользователю (он не программист) установить инструмент «Content Factory»
и подключить его к своему Codex. Сделай всё сам, по шагам ниже. На каждом шаге, где нужны данные
от пользователя (API-ключ, доступ к репозиторию), — **спроси его простыми словами** и подожди
ответ. Не пропускай проверки. В конце — короткая инструкция, как этим пользоваться.

**Что это:** единая обёртка над платными AI-моделями fal.ai и Replicate. Пользователь говорит,
что сгенерировать, — инструмент запускает модель и скачивает результат в папку проекта. Здесь
используются **только fal.ai и Replicate** — им нужен лишь API-ключ, никакого локального железа
или серверов. Другие бэкенды репозитория (ComfyUI, Nano, Dreamina) НЕ настраивай и не запускай.

---

## Шаг 0. Проверь окружение

- `python --version` → должно быть **3.10 или выше**. Если Python нет/старый — помоги установить.
- `git --version` → git должен быть. Если нет — установи.
- Codex CLI уже есть (ты в нём работаешь). Найди путь к его конфигу: обычно `~/.codex/config.toml`.

Определи ОС пользователя (Windows / macOS / Linux) — команды и пути ниже адаптируй под неё.

## Шаг 1. Получить код

Репозиторий: **https://github.com/Znen/content_factory.git**

```bash
git clone https://github.com/Znen/content_factory.git content-factory
cd content-factory
```

⚠️ Если `git clone` падает с ошибкой доступа (`repository not found` / `authentication`) — репозиторий
**приватный**. Тогда скажи пользователю: «Репозиторий закрыт — попроси владельца (Znen) либо сделать
его публичным, либо добавить тебя в collaborators на GitHub и залогинься в git (`gh auth login` или
Personal Access Token)». Дождись, пока доступ появится, и повтори clone.

## Шаг 2. Установить

```bash
python -m pip install -e ".[dev]"
```

Проверь, что появилась команда: `gf --help` (или, если `gf` не в PATH, используй везде дальше
`python -m gf.cli` вместо `gf`).

## Шаг 3. Взять API-ключ у пользователя

Спроси пользователя, каким сервисом он будет пользоваться, и есть ли у него ключ:

- **fal.ai** — ключ создаётся на https://fal.ai → Dashboard → Keys. Нужны положенные кредиты (платно).
- **Replicate** — токен `r8_...` на https://replicate.com → Account → API tokens. Тоже платно.

Если ключа нет — простыми словами проведи его: «Зайди на сайт, зарегистрируйся, создай ключ,
пополни баланс, пришли мне ключ». **Ключ — личный, платит по нему сам пользователь.**

Когда пользователь даст ключ — создай файл `.env` в корне проекта (он уже в `.gitignore`, в git
не попадёт). Впиши нужное:

```
FAL_KEY=<ключ пользователя>
REPLICATE_API_TOKEN=<токен пользователя>
```

Достаточно того, что он будет использовать (можно только `FAL_KEY`). **Не показывай ключ в выводе
и не коммить `.env`.**

## Шаг 4. Проверить, что ключ рабочий

```bash
gf serve          # должен запуститься MCP-сервер без ошибок; останови (Ctrl+C)
gf fal-list-workflows   # с верным FAL_KEY — вернёт список (возможно пустой), НЕ ошибку 401
```

Если `serve` поднимается и `fal-list-workflows` не ругается на авторизацию — ключ рабочий.
(Если пользователь дал только Replicate — пропусти `fal-list-workflows`.)

## Шаг 5. Подключить к Codex

Открой `~/.codex/config.toml` (формат **TOML**). Добавь блок (используй абсолютный путь к папке
проекта в `cwd`, чтобы `.env` точно нашёлся):

```toml
[mcp_servers.generation_factory]
command = "gf"
args = ["serve"]
cwd = "<абсолютный путь к склонированной папке content-factory>"
```

Если `gf` не находится по имени — замени на:

```toml
[mcp_servers.generation_factory]
command = "python"
args = ["-m", "gf.cli", "serve"]
cwd = "<абсолютный путь к папке content-factory>"
```

Проверь:

```bash
codex mcp list
```

Должен появиться `generation_factory` с инструментами `gf_fal_run`, `gf_replicate_run`,
`gf_fal_list_workflows`. Если сервера нет — проверь TOML-синтаксис и что `gf serve` (или
`python -m gf.cli serve`) запускается вручную из папки проекта.

## Шаг 6. Показать пользователю, как пользоваться

Объясни простыми словами и приведи пример. Пользоваться можно **прямо через тебя** (Codex):
пусть просто просит, например — «сгенерируй картинку через fal-ai/nano-banana-pro, промпт …,
проект — <абсолютный путь к его рабочей папке>». Ты вызовешь `gf_fal_run`, результат появится в
`<project>/media/generated/<дата>/`.

**Ключевые правила, которые донеси пользователю:**
- Всегда указывать **абсолютный путь** к папке проекта (иначе инструмент откажет).
- Вызовы **платные помодельно** — для проб брать дешёвые/быстрые модели (например `flux-schnell`
  на Replicate). Стоимость пишется в `<project>/media/.gf_cost_log.jsonl`.
- Каталоги моделей: fal — https://fal.ai/models · Replicate — https://replicate.com/explore

**Примеры на будущее (можешь показать):**
```bash
gf fal-run <АБС_ПУТЬ_ПРОЕКТА> fal-ai/nano-banana-pro "{\"prompt\":\"cinematic portrait\"}"
gf replicate-run <АБС_ПУТЬ_ПРОЕКТА> black-forest-labs/flux-schnell "{\"prompt\":\"a red fox\"}"
```

## Ограничения (упомяни, если всплывут)

- Работают **только fal и Replicate**. ComfyUI/Nano/Dreamina не трогай — им нужно локальное железо.
- Передача **локального файла** в модель (референс) делается маркером `@путь`, но регэксп заточен
  под **Windows-пути** (`@C:/path/file.png`). На macOS/Linux POSIX-пути (`@/home/...`) пока не
  распознаются: генерация **по текстовому промпту** работает везде, а загрузка локальных
  референсов на не-Windows потребует доработки кода (сообщи пользователю, не пытайся чинить сам).
