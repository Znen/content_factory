# Каталог моделей Magnific (Freepik-платформа) — справочник

**Источник: веб-доки Freepik/Magnific (`docs.freepik.com` → 301 редиректит на `docs.magnific.com`, плюс консьюмерская страница сравнения `magnific.com/ai/docs/image-ai-models`). MCP-каталог (`images_models_list`/`video_models_list`) НЕ сверялся — живой ответ инструмента может отличаться по составу/именам моделей.** Собрано: 2026-07-06.

Не цель для `gf.writer` (имя с `_`, `list_targets()` его пропускает) — это справочник для человека/LLM-райтера, выбирающего модель перед вызовом Hermes-инструментов `images_generate`/`images_upscale`/`video_generate`.

## Важная оговорка про слой Hermes

Наш завод (`content-factory`) Magnific **не оборачивает** — Hermes зовёт облачный MCP `mcp.magnific.com` напрямую (`images_generate`, `images_upscale`, `video_generate`, `images_models_list`, `video_models_list`, `simulate_cost`, `creations_*`). Паспорта в этой папке дают промпт-конкретику **по документации сырого Freepik REST API** (`api.freepik.com` / `api.magnific.com`, эндпоинты вида `/v1/ai/<model>`) — это не гарантированно те же имена полей, что принимает MCP-обёртка `images_generate`. Если вызов инструмента вернёт ошибку валидации параметра — доверяй фактическому ответу инструмента, а не этому файлу; паспорта нужны прежде всего для того, **как писать текст промпта** и на что модель реагирует, а не как точная схема вызова.

## Особенности площадки (детально — короткие версии есть в каждом паспорте)

- **Кредиты.** Перед дорогой генерацией (высокое разрешение/4K, длинное видео, батч правок) — всегда `simulate_cost` первым вызовом, не оценка на глаз. Магнификовский биллинг — кредитный, разные модели и разрешения стоят по-разному; страница с точными цифрами (`magnific.com/ai/docs/...pricing`) на момент исследования цифр не раскрывала — не выдумывай конкретные числа кредитов, полагайся на `simulate_cost` как источник истины на момент вызова.
- **Загрузка локальных файлов.** `creations_upload_image` принимает **только http(s)-URL** — локальный путь на диске (`R:\...\media\...png`) он не примет. Правильный флоу для локального файла: `creations_request_upload` (получить presigned-параметры) → `PUT` файла по этим параметрам → `creations_finalize_upload` (получить финальный http(s)-URL для использования как референс/структурная картинка/стартовый кадр видео). Это касается ЛЮБОЙ модели в этом каталоге, где нужен референс/входное изображение.
- **Circuit-breaker (хроническая проблема, см. память `hermes-integration`).** После 3 подряд неудачных вызовов magnific-MCP клиент Hermes включает circuit-breaker и **локально** отбивает все последующие вызовы этого сервера — выглядит как «magnific лежит», хотя причина в клиенте, не в площадке. Частая причина трёх ошибок подряд — как раз попытка скормить локальный путь напрямую в `creations_upload_image` вместо upload-флоу выше. Лечится рестартом gateway; автоматического сброса по времени не наблюдалось. Если несколько вызовов подряд падают — сначала проверь: (1) это точно http(s)-URL, не локальный путь; (2) не превышен ли лимит референсов конкретной модели (см. паспорта — они разные!); и только потом — эскалируй как «площадка легла».

## Рабочий набор (детальные паспорта) и обоснование выбора

Критерии из брифа: (а) t2i с multi-ref — кандидат на финалы «лицо+локация» вместо заблокированного Nano; (б) фотореализм/кино-стилистика под проекты Lion Films; (в) минимум одна видео-модель.

| Модель | Паспорт | Роль в наборе |
|---|---|---|
| **Mystic** | [`mystic.md`](mystic.md) | (б) — флагманский фотореализм/кино-портреты площадки (эксклюзив Freepik, не переносится на другие хостинги). НЕ подходит для сшивки «лицо+локация» буквально — структурный/стилевой референс, не identity-lock. |
| **Seedream 4.5 Edit** | [`seedream-v4-5-edit.md`](seedream-v4-5-edit.md) | (а) — «strong character control and multi-image fusion»; 1-5 референсов; главный кандидат на финалы «лицо с фото 1 + локация с фото 2» вместо Nano. |
| **Nano Banana Pro** | [`nano-banana-pro.md`](nano-banana-pro.md) | (а) — Google Gemini image на Magnific (verified live); t2i ИЛИ multi-ref 0-4; **рабочая замена заблокированному локальному Nano** (Gemini-403). Aspect в обычном `"9:16"`-формате (не enum). |
| **Flux Kontext Pro** | [`flux-kontext-pro.md`](flux-kontext-pro.md) | точечные правки уже выбранного финала (смена фона/одежды/времени суток без пересборки сцены) — не входит в исходные три критерия напрямую, но закрывает частый в Lion Films кейс «доработать финал», где Seedream/Mystic избыточны (пересоздают сцену с нуля, а не редактируют её). |
| **Kling 2.5 Pro** (image-to-video) | [`kling-v2-5-pro.md`](kling-v2-5-pro.md) | (в) — единственная видео-модель набора; оживление winner-кадра (`gf_contact_sheet`/курация уже выбрала лучший кадр → Kling его анимирует). |

Почему не Nano Banana / Imagen / Flux 2 Pro / Ideogram и т.д. в детальный набор — см. таблицу каталога ниже: они либо дублируют роль уже выбранной модели (Flux 2 Pro тоже multi-ref, но без явного «character control» акцента Seedream), либо не проверены по доступности (Nano Banana семейство — по каталог-странице площадки это Google-модели, а НЕ наш локальный Gemini-сервер `gf/backends/nano.py`, который заблокирован Gemini-403; на Magnific-площадке они могут быть рабочими — не проверялось), либо не относятся к фотореализму/кино (Ideogram/Recraft — типографика/дизайн-графика).
