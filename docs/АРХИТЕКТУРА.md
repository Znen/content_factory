# Архитектура — Content Factory (`generation-factory`)

**Дата:** 2026-07-05
**Отражает:** фактически реализованный код Фазы 1 (12 коммитов, `a6b03c4..92976da`).

## 1. Обзор

Python-пакет `gf` — MCP-сервер по образцу `knowledge-factory`:

```
config (@dataclass)  →  build_core()  →  mcp_server (3 транспорта)  →  cli
                                    ↘  бэкенды (чистые HTTP-клиенты)
```

Бэкенды — **тонкие HTTP-клиенты без бизнес-логики**. Cost-gating, раскладка проекта и оркестрация живут в обёртках инструментов (`_*_impl`), а не в бэкендах.

## 2. Дерево пакета

```
gf/
├── config.py          @dataclass Settings + load_settings() (env-префикс GF_, без pydantic)
├── pricing.py         estimate(backend, n) -> usd  (чистая функция, без реестра)
├── budget.py          лог .gf_cost_log.jsonl + мягкий кап (log_cost/spent/check)
├── media.py           раскладка media/generated/<дата>/ (drafts_dir/shot_dir/generated_dir/next_index)
├── core.py            Core + build_core(settings) — единый билдер для cli и server
├── mcp_server.py      _generate_draft_impl / _generate_final_impl / _write_prompt_impl, build_server(), run_server(http)
├── cli.py             Typer: version / serve / generate-draft / generate-final / write-prompt / list-targets + main() (UTF-8)
├── writer.py          промпт-райтер: паспорта + один вызов Claude -> {prompt, negative, params, notes}
├── promptdocs/        markdown-паспорта моделей (frontmatter + гайд), package-data пакета gf
│   ├── comfyui/sdxl-juggernaut.md
│   ├── nano/gemini-image.md
│   └── magnific/{mystic,seedream-v4-5-edit,flux-kontext-pro,kling-v2-5-pro,_catalog}.md
├── backends/
│   ├── nano.py        Nano Banana — ported из старого агента, отвязан от tools.common
│   └── comfyui.py     ComfyUI REST-клиент — написан с нуля
└── workflows/
    └── sdxl_txt2img_api.json   API-format шаблон (PLACEHOLDER_*), параметризуется
```

Один тест-файл на модуль (`tests/test_*.py`), фейковые HTTP-сессии, `conftest.py` гейтит `live`-тесты.

## 3. Ответственности модулей

- **config.py** — единственный источник дефолтов; читает `os.environ` с in-code значениями, `load_dotenv()` в try/except. Токен: `os.environ.get("GF_MCP_TOKEN") or None`.
- **pricing.py** — плоская оценка $/картинка (nano ≈ $0.04, comfyui = $0). Без I/O, без реестра.
- **budget.py** — владеет форматом cost-лога (`{"ts","backend","n","cost_usd","note"}`); `check()` возвращает `{allowed, spent, cap, reason}`; нулевая стоимость всегда allowed; устойчив к битым строкам лога.
- **media.py** — раскладка из storage-спеки; создаёт директории; `next_index` для нумерации `draft-NN`.
- **core.py** — `build_core(settings)` → `Core`; провязан в `build_server()` и CLI (единая точка сборки; в Фазе 1 несёт только settings — расширится, когда появятся stateful-handles).
- **backends/nano.py** — login→токен-кэш→`/api/gemini` (bearer+X-App-Auth); multi-ref как base64-массивы (`base64Datas`+`mimeTypes`, ≤4); ответ `imageUrl` (data-URI) → PNG. Единственное публичное исключение — `NanoError` (внутренний `AuthExpired` наружу не течёт; при двойном 401 конвертируется).
- **backends/comfyui.py** — `load_workflow`/`build_workflow` (deep-copy, не мутирует шаблон) + `generate`: `POST /prompt` → poll `GET /history/{id}` → download `GET /view` → `draft-NN.png`.
- **writer.py** — чистая функция `write_prompt()`: собирает контекст (паспорт цели + `style.md` + аргументы вызова), делает один forced tool call к Claude, логирует провенанс и стоимость. См. §9.
- **mcp_server.py** — см. §4–5.

## 4. Поток инструмента (cost-gating)

Обёртки `_generate_draft_impl` / `_generate_final_impl` (бэкенды инъектируются параметрами `comfy=`/`nano=`/`budget=` — отсюда тестируемость без сети):

```
estimate(cost)  →  budget.check(project, cost, cap)
   ├─ blocked → return {"error", "images": [], "spent_usd"}   (ничего не генерируется)
   └─ allowed → backend.generate(...)  →  budget.log_cost(...)  →  return {"images", "backend", "cost_usd", "spent_usd"}
```

Стоимость логируется **только после успешной** генерации — упавший вызов не биллится. Финалы пишутся в `media.generated_dir(project, date)` (без побочного создания `_drafts/`).

## 5. Транспорты (`run_server(http)`)

1. **stdio** (дефолт) — `mcp.run(transport="stdio")`. Для локального Hermes, запускающего сервер как subprocess.
2. **HTTP + bearer** (`http=True` и задан `GF_MCP_TOKEN`) — `mcp.streamable_http_app()` оборачивается middleware `_make_bearer_middleware(token)` (сравнение через `hmac.compare_digest`, 401 иначе), поднимается uvicorn на `GF_MCP_BIND:GF_MCP_PORT`.
3. **plain streamable-HTTP** (`http=True`, без токена) — доверенный localhost.

FastMCP импортируется **лениво** внутри `build_server()` (чтобы импорт `gf.cli` оставался дешёвым). Сервер: `FastMCP("generation-factory", host=…, port=8766)`, инструменты через `@mcp.tool()`, docstring = описание инструмента.

## 6. Данные на диске

- **Медиа/артефакты:** `<project>/media/...` (см. [ТЗ](ТЗ.md) §2.2). `/media/` в `.gitignore` самого content-factory (артефакты живут в папках проектов, не в репо инструмента).
- **Cost-лог:** `<project>/media/.gf_cost_log.jsonl`.
- **Промпты (Фаза 2):** `generated/<дата>/shot-XX/prompts/iter-*.json`.
- **Токен Nano:** `~/.lionfilms/nitro_banana_token.json` (кэш, вне репо).

## 7. Интеграция с Hermes (Фаза 4)

Регистрация как третьего MCP рядом с kf и magnific: `hermes mcp add generation_factory` (stdio: `command`/`args` на `gf serve`, или HTTP+bearer как у kf). Инструменты у Hermes получат префикс: `mcp_generation_factory_gf_generate_draft` и т.д. Детали и ловушки подключения — в памяти `hermes-integration` (⚠️ uv-Python vs venv-Python в `Hermes_Gateway.cmd`).

## 8. Осознанные отступления от буквального дизайна

1. Cost-gating — **чистая версия**, не перенос старого (тот завязан на выброшенную структуру).
2. ComfyUI-клиент **написан с нуля** (в старом агенте Python-клиента не было — только сторонний Node-MCP).
3. Пакет `gf`, порт `8766`; дефолт-модель черновиков `juggernautxl_ragnarok.safetensors` (конфигурируемо через `GF_COMFYUI_CKPT`/`GF_COMFYUI_WORKFLOW`).
4. Bearer через `hmac.compare_digest` (в kf был timing-unsafe `!=` — исправлено здесь).
5. **`promptdocs/` живёт внутри пакета `gf/` (`gf/promptdocs/`), а не в корне репо рядом с `workflows/`, как описано в спеке** (`docs/superpowers/specs/2026-07-06-prompt-layer-design.md`, §«Компоненты»). Причина: файлы за пределами пакета не попадают в package-data при установке (`pip install`/`sdist`) — путь в корне репо ломает `promptdocs/` в собранном пакете вне dev-checkout'а. `writer.PROMPTDOCS` резолвится как `Path(__file__).resolve().parent / "promptdocs"`, т.е. относительно самого пакета, а не `_REPO_ROOT`.

## 9. Промпт-слой (`writer.py` + `promptdocs/`)

Отдельный слой, переписывающий текст задачи в промпт под конкретную генеративную площадку до её вызова — Hermes (deepseek) без него пишет промпты слабо и без знания синтаксиса площадки. Дизайн: `docs/superpowers/specs/2026-07-06-prompt-layer-design.md`.

```
gf_write_prompt(project, target, task, refs?) ──┐
                                                 │
        ┌──────────── gf/writer.py ◄────────────┘
        │  1. паспорт цели   gf/promptdocs/<target>.md   (frontmatter + гайд)
        │  2. стиль проекта  <project>/prompts/style.md  (опционально)
        │  3. задача/рефы/аспект/extra — из аргументов вызова
        │        ↓
        │  один forced tool call к Claude API (`emit_prompt`)
        │        ↓
        │  {prompt, negative, params, notes}
        │        ↓
        │  лог: <project>/prompts/YYYY-MM-DD-<slug>-NN.md
        └──► результат вызывающему
```

Три способа использования:

1. **Явный** — `gf_write_prompt(target="magnific/mystic", ...)`: возвращает структурированный промпт, Hermes сам зовёт площадку. Единственный способ покрыть промпт-слоем площадки, которые `gf` не оборачивает бэкендом (`magnific/*`).
2. **Автоматический** — `gf_generate_draft/final(..., raw=False)` (`raw=False` — новый default): текст `prompt` трактуется как задача и прогоняется через `write_prompt()` под цель бэкенда (`GF_WRITER_DRAFT_TARGET`/`GF_WRITER_FINAL_TARGET`) перед вызовом ComfyUI/Nano; `raw=True` — короткое замыкание, старое поведение (текст дословно в модель).
3. **Справочный** — `gf_list_targets()`: список целей строится из frontmatter'ов `promptdocs/` (файлы `_*.md`, например `magnific/_catalog.md`, пропускаются — это справочники, не цели).

**Явный/авто поток различаются обработкой ошибок** (`_maybe_rewrite()` в `mcp_server.py`):

- **Явный путь — fail-closed.** Нет ключа/паспорта/API-ошибка после ретрая → `write_prompt()` кидает `WriterError`, `_write_prompt_impl` ловит и возвращает `{"error": ...}`. Промпт-слой не должен возвращать неполный/угаданный результат по явному запросу.
- **Авто-путь — fail-open с флагом.** `_maybe_rewrite()` ловит `WriterError` и вместо падения возвращает исходный текст задачи как есть + `writer_skipped: "<причина>"` в финальном ответе инструмента — промпт-слой никогда не должен остановить генерацию сам по себе. Известный неполный кусок: при срабатывании budget-гейта (`gate["allowed"] is False`) ранний `return` в `_generate_draft_impl`/`_generate_final_impl` не пробрасывает уже посчитанные `prompt_used`/`writer_skipped` — см. ЗАДАЧНИК.

`writer.py` — чистая функция с ровно одним LLM-вызовом (+1 ретрай на невалидной по схеме `emit_prompt` попытке); весь контекст собирает детерминированный код. `anthropic.Anthropic` создаётся лениво (`_make_client()`), инжектируется в тестах (`client=`) — паттерн `session=` из `backends/comfyui.py`. Стоимость считается из `usage.input_tokens/output_tokens` (`pricing.estimate_llm`) и логируется в тот же `.gf_cost_log.jsonl`, что и генерации (backend `"writer"`), но `image_cap_usd`-гейтом не блокируется.
