# Техническое задание — Content Factory (`generation-factory`)

**Дата:** 2026-07-05
**Статус:** Фаза 1 — выполнена; Фазы 2–4 — планируются.

## 1. Назначение

Отдельный MCP-сервер, дающий агенту Hermes генеративные инструменты для визуального препрода. Ставится рядом с уже подключёнными к Hermes `knowledge-factory` и `magnific`.

## 2. Функциональные требования

### 2.1. MCP-инструменты

| Инструмент | Фаза | Что делает |
|---|---|---|
| `gf_generate_draft(project, prompt, n, negative, seed, raw=False)` | ✅ 1 / ✅ Ф-П3 | N дешёвых черновиков через ComfyUI → `media/generated/<дата>/_drafts/draft-NN.png`. `raw=False` (default): `prompt` трактуется как задача и переписывается промпт-райтером под `comfyui/sdxl-juggernaut`; `raw=True` — текст уходит в модель дословно (старое поведение) |
| `gf_generate_final(project, prompt, refs[], aspect, raw=False)` | ✅ 1 / ✅ Ф-П3 | Финал через Nano Banana (≤4 multi-референса) → `media/generated/<дата>/`. `raw=False`: переписывается под `nano/gemini-image`; `raw=True` — дословно |
| `gf_write_prompt(project, target, task, refs[], aspect, extra)` | ✅ Ф-П3 | Явный вызов промпт-райтера для любой цели из `gf_list_targets` (в т.ч. `magnific/*` — площадки, которые завод не оборачивает) |
| `gf_list_targets()` | ✅ Ф-П3 | Список целей райтера с их паспортами (frontmatter `gf/promptdocs/`) |
| `gf_save_asset(project, image, kind, name)` | ⬜ 2 | Сохранить выбранное в кирпич `locations/<name>/` или `characters/<name>/` |
| `gf_assemble_shot(project, shot, character, location, prompt, date)` | ⬜ 2 | Сборка кадра (лицо+локация multi-ref) → `generated/<дата>/shot-XX/` + промпт в `prompts/` |
| `gf_contact_sheet(project, selection)` | ⬜ 3 | Контакт-лист ПО ЗАПРОСУ (за дату / последние N / список) |

`project` — абсолютный путь к папке проекта; Hermes передаёт его явно.

### 2.2. Раскладка медиа проекта (storage-спека)

```
<project>/media/
├── references/{characters,locations,look-and-feel}/   ← входящее из брифа
├── locations/<name>/                                  ← созданные кирпичи-локации
├── characters/<name>/                                 ← утверждённые персонажи
├── generated/<YYYY-MM-DD>/
│   ├── _drafts/draft-NN.png
│   └── shot-XX/{iter-*.png, prompts/iter-*.json}
└── storyboards/
```

### 2.3. Промпты / память процесса

- Промпты сохраняются рядом с картинками: `generated/<дата>/shot-XX/prompts/iter-*.json` (промпт + backend + референсы + seed + дата), связь по имени.
- Назначение: (а) отдать клиенту; (б) воспроизвести удачное / избежать неудачного. Hermes перед новым кадром читает прошлые удачные промпты.

### 2.4. Cost-gating

- Каждая генерация логируется в `<project>/media/.gf_cost_log.jsonl` (оценка стоимости).
- Опциональный мягкий кап `GF_IMAGE_CAP_USD`: генерация, превышающая накопленный лимит проекта, **отклоняется** (возврат `{"error": ...}`, ничего не генерируется).
- Нулевая стоимость (локальный ComfyUI) **не блокируется** капом никогда.

### 2.5. Промпт-слой (промпт-райтер)

Причина: Hermes (deepseek) сам пишет слабые промпты для генеративных моделей — не знает синтаксис конкретной площадки, теряет контекст брифа. Отдельный слой поручает написание промпта Claude API, по markdown-«паспорту» модели. Спека: `docs/superpowers/specs/2026-07-06-prompt-layer-design.md`.

- **Инструменты:** `gf_write_prompt` (явный вызов, работает для любой цели, включая `magnific/*` — площадки, которые `gf` не оборачивает своими бэкендами) и `gf_list_targets` (справочник доступных целей); плюс неявный авто-путь `raw=False` внутри `gf_generate_draft`/`gf_generate_final` (draft переписывается под `comfyui/sdxl-juggernaut`, final — под `nano/gemini-image`; `raw=True` — старое поведение без райтера).
- **Цели/паспорта:** markdown-файл с YAML-frontmatter (`gf/promptdocs/<platform>/<model>.md`), обязательные ключи `target/platform/syntax/negative/refs/updated`; тело — структура идеального промпта, типовые фейлы, примеры «задача → плохо → хорошо». V1 — 6 целей: `comfyui/sdxl-juggernaut`, `nano/gemini-image`, `magnific/{mystic,seedream-v4-5-edit,flux-kontext-pro,kling-v2-5-pro}`; плюс `magnific/_catalog.md` — справочник «когда какую модель Magnific брать» (не цель, `gf_list_targets` его не считает).
- **Контекст вызова:** паспорт цели + `<project>/prompts/style.md` (опционально, отсутствие — не ошибка) + задача/референсы(имена)/аспект/доп.указания из аргументов → один forced tool call к Claude (`emit_prompt`) → `{prompt, negative, params, notes}`. Провенанс логируется в `<project>/prompts/YYYY-MM-DD-<slug>-NN.md`.
- **Конфиг (`GF_WRITER_*`):** `GF_WRITER_MODEL` (default `claude-sonnet-5`), `GF_WRITER_MAX_TOKENS` (default 2000), `GF_WRITER_ENABLED` (default true — выключен: явный вызов возвращает ошибку, авто-путь тихо пропускает райтера), `GF_WRITER_DRAFT_TARGET`/`GF_WRITER_FINAL_TARGET` (цели авто-пути, дефолты — comfyui/nano выше). Ключ — стандартный `ANTHROPIC_API_KEY` (env/`.env`).
- **Обработка ошибок:** явный `gf_write_prompt` — fail-closed (`{"error": ...}` с инструкцией, без traceback); авто-путь — fail-open (генерация продолжается с текстом задачи как есть, в ответе флаг `writer_skipped: "<причина>"`).
- **Статус:** код реализован и покрыт unit-тестами (без сети, инжектируемый клиент); бесключевые CLI-смоуки (`gf list-targets`, чистая fail-closed ошибка `gf write-prompt` без ключа) пройдены. Живой смоук (реальный ответ Claude) и регистрация новых инструментов в Hermes-gateway (рестарт discovery) ждут `ANTHROPIC_API_KEY` в системе.

## 3. Нефункциональные требования

- **Портируемость / local-first:** без внешних облачных зависимостей в ядре; всё локально (ComfyUI на RTX 4070, Nano-сервер на localhost). Секреты — вне репозитория.
- **Платформа:** Windows 11, Python ≥ 3.10 (проверено на 3.10.11).
- **Пакет:** `gf`; CLI `gf`; env-префикс `GF_`; MCP-имя `generation-factory`; порт по умолчанию **8766** (чтобы не биться с kf `:8765`).
- **Транспорты MCP:** stdio (по умолчанию, для локального Hermes-subprocess); HTTP+bearer (`hmac.compare_digest`) когда задан `GF_MCP_TOKEN`; plain streamable-HTTP иначе.
- **Тесты:** каждый модуль покрыт; HTTP-бэкенды тестируются с инъекцией фейковой сессии (без сети). Реальные внешние вызовы — за маркером `live` (`GF_RUN_LIVE=1`).
- **Простота:** без pydantic (обычный `@dataclass` config), без БД-стека (в отличие от kf).
