## 1. Контекст: что такое паспорт и промпт-слой

Промпт-слой завода (`gf/writer.py` + `gf/promptdocs/`) одним вызовом Claude превращает сырую
задачу в грамотный промпт по «паспорту» модели. Паспорт = markdown с YAML-frontmatter: frontmatter
машиночитаем (`gf_list_targets` строит из него список целей), тело вставляется в system prompt
райтера как экспертиза по конкретной модели.

Существующие паспорта: `comfyui/sdxl-juggernaut`, `nano/gemini-image`, `magnific/{mystic,
seedream-v4-5-edit, flux-kontext-pro, kling-v2-5-pro}` + справочник `magnific/_catalog.md`.

**Как это будет использоваться (явный режим):** `gf_write_prompt(project, target="video/veo-3-1",
task="...")` → возвращает готовый промпт **Hermes'у**, а Hermes сам исполняет его тем путём, каким
захочет. Заводу НЕ нужен видео-бэкенд для этого — паспорт самоценен как знание.

## 3. Дизайн-решения (не пересматривать без Кира)

| Вопрос | Решение |
|---|---|
| **Группировка** | Новая папка `gf/promptdocs/video/`. Синтаксис промпта определяется **самой моделью**, а не площадкой доступа, поэтому ключуем по модели/семейству, а не по хостингу. |
| **`platform` во frontmatter** | Семейство модели: `veo`, `seedance`, `wan`, `runway` (нейтрально к пути исполнения). |
| **Путь исполнения** | Пока НЕ выбран — Кир хочет промпты как самоценность. Паспорта работают в явном режиме (`gf_write_prompt`). Никакого бэкенда/интеграции сейчас. |
| **Kling** | Остаётся в `magnific/` как есть (его путь уже выбран — Magnific). НЕ мигрируем. |
| **Модели** | Veo 3.1, Seedance 2.0, Wan 2.5, Runway Gen-4. Оба режима t2v+i2v в одном паспорте с разделами. |

**Важное про t2v vs i2v:** это два разных входа, и промпт для них пишется по-разному:
- **t2v** (текст → видео): промпт описывает и **композицию сцены**, и **движение**, и камеру, и стиль
  (модель рисует всё с нуля) — ближе к структуре image-паспортов + слой движения/камеры/темпа.
- **i2v** (кадр → видео): композиция уже задана стартовым кадром, промпт описывает **только движение
  и камеру** — как в паспорте Kling. Референс (`refs: single`) — стартовый кадр.

Отрази оба режима явными разделами в каждом паспорте.

## 4. Структура каждого паспорта (по образцу `kling-v2-5-pro.md`)

```markdown
---
target: video/<model>
platform: <veo|seedance|wan|runway>
syntax: natural
max_len: <из доки — ориентир в символах/токенах>
negative: <true|false — есть ли у модели negative-параметр>
refs: single            # для i2v-стартового кадра; уточни, поддерживает ли модель больше
updated: 2026-07-09
sources: [<официальные доки + гайды, по которым писал>]
---
# Как писать промпт для <Model> (t2v + i2v[ + audio])

Контекст: <что за модель, что умеет, чем сильна, длительности/разрешения, ключевые ограничения>.

## Text-to-video (t2v)
<структура промпта: сцена/субъект → действие/движение → камера → темп → стиль/свет;
чем отличается от image-промпта — тут есть ВРЕМЯ и ДВИЖЕНИЕ>

## Image-to-video (i2v)
<как в Kling: промпт описывает только движение+камеру, композиция задана кадром;
держать промпт согласованным со стартовым кадром>

## [Только Veo] Аудио
<нативная генерация звука/диалогов/музыки: как задавать реплики (кавычки?), звуковую
атмосферу, музыку; типовые ошибки при работе со звуком>

## [Только Seedance] Multi-shot / clips[]
<механика нескольких кадров/сцен в одном запросе — Hermes уже касался этого в magnific-mcp;
как раскадровывать, keyframes>

## Negative prompt        # если модель поддерживает
<что описывать — нежелательные движения/артефакты, не SDXL-«качество»>

## Параметры
<таблица: duration, resolution/aspect, fps, seed, cfg/guidance, audio-флаги — из доки, со ссылкой>

## Особенности
<кредиты/лимиты/специфика; если модель доступна на Magnific — краткая отсылка к _catalog.md>

## Типовые фейлы
<5+ конкретных анти-паттернов, специфичных для ЭТОЙ модели>

## Примеры «задача → плохо → хорошо»
<3-5 примеров, покрывающих t2v и i2v (и audio для Veo). Пример = задача (можно RU) →
плохой промпт с разбором почему → хороший промпт + параметры. Как в Kling-паспорте.>
```

## 5. Источники для research (знаний почти ноль — это главная работа)

Прежде чем писать каждый паспорт — собери актуальную фактуру. Приоритет: **официальная
документация модели**, затем проверенные prompt-гайды. Для каждого паспорта зафиксируй
использованные источники в `sources:` frontmatter.

- **Veo 3.1:** Google DeepMind / Google AI / Vertex AI Veo prompting guide (структура промпта,
  нативный звук и диалоги — фишка Veo 3, «audio cues»/`"dialogue in quotes"`, длительности,
  разрешения). Ищи официальный «Veo prompt guide».
- **Seedance 2.0:** ⭐ **ГЛАВНЫЙ первоисточник — старый видео-завод, где Seedance реально
  исполнялся через Dreamina CLI (JiMeng / 即梦, ByteDance):**
  - `Q:\Lion Films. AI studio\tools\dreamina-cli\DREAMINA_CLI.md` — полное руководство CLI 1.4.1:
    команды (`text2video`, `image2video`, `frames2video`, `multiframe2video`, `multimodal2video`),
    модели (`seedance2.0` / `2.0fast` / `2.0_vip` / `2.0fast_vip`), параметры (duration 4–15с, ratio,
    720p/1080p), async-модель (submit → `submit_id` → `query_result`, флаг `--poll`), и — самое
    ценное — **реальные подводные камни из практики**: resolution-matching rule (720p→1280×720 q85
    <500KB, 1080p→1920×1080 q92 <1MB), лимит файла >1–2МБ, **пути с пробелами → тихий сбой с
    частичным списанием кредитов**, **pre-TNS контент-фильтр** (тело/нагота списывают кредиты),
    1080p только через `multimodal2video --model_version=seedance2.0_vip`.
  - `Q:\Lion Films. AI studio\tools\videogen\backends\dreamina.py` — рабочий backend-образец
    (subprocess-обёртка + staging путей без пробелов + retry/backoff + VIP-очередь). Это образец
    ОРКЕСТРАЦИИ (для будущего видео-бэкенда), но подтверждает и промпт-специфику.
  - Прочитай оба ПЕРВЫМИ — они дают проверенную вживую фактуру, а не догадки. Дополнительно:
    ByteDance / Volcengine (火山引擎) Seedance docs и скилл Hermes `magnific-mcp/SKILL.md`
    (`clips[]`/keyframes), см. `docs/hermes-prompting-analysis-2026-07-06.md` §4.
  - **Путь исполнения Seedance известен (Dreamina CLI)** — в отличие от Veo/Wan/Runway. Отрази это
    в паспорте: команды и режимы маппятся на CLI (`image2video` = i2v, `text2video` = t2v,
    `multiframe2video` = multi-shot вместо абстрактного `clips[]`). `platform: seedance` оставь,
    но в теле паспорта укажи Dreamina CLI как основной путь и его специфику.
- **Wan 2.5:** Alibaba Wan (Tongyi Wanxiang) official docs / prompt guide; t2v+i2v-1080p.
- **Runway Gen-4:** help.runwayml.com — официальный Gen-4 prompting guide (Runway любит
  структуру «камера + субъект + действие + освещение», короткие точные промпты).
- **Кросс-модельный источник:** в системе есть скилл **`ai-video-generation`** (Veo 3.1/3,
  Seedance 2.0, Kling, Wan, Grok через inference.sh) — полезен как сводка возможностей и
  режимов; используй как ориентир, но параметры сверяй с официальными доками.

**Предупреждение:** модели быстро обновляются. Если факт не подтверждён источником — помечай его
как эвристику («по практике площадки»), как это сделано в Kling-паспорте, а не выдавай за точную
спецификацию API.
