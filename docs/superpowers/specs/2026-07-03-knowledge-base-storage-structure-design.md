# Knowledge Base Storage Structure — Design Spec

**Date:** 2026-07-03
**Status:** Approved (brainstorm)
**Scope:** Единая структура хранения проектных данных на `Q:` — документы + медиа + рабочие файлы производства. Первое применение — `20_business` (Lion Films подряд + собственная AI-студия). Паттерн общий.

## Guiding principle

**Одна папка = один проект, всё касающееся проекта — внутри неё.** Чем проще, тем лучше. Разрозненные production-области (`WORK`, `Lion Films. Projects`) как отдельные сущности **упраздняются** — их содержимое сводится в единую по-проектную структуру.

## Context (текущее состояние)

- `Q:\1brain` — индексируемая база знаний (307 текстовых + лёгкие медиа). По ней ходит `kf ingest`, читает Hermes.
- Проекты раскиданы: `1brain\20_business\lion_films` (214 бизнес-документов, плоско по типам), `Q:\WORK\10_Work_Projects` (активное AI-производство с пайплайном `00_brief..05_review`, реестрами шотов/референсов), `Q:\Lion Films. Projects`, архив `F:\STORE\60_Archive`.
- Тяжёлые видео-проекты живут на отдельном SSD.
- WORK-пайплайн признан пользователем **избыточным**; его внутренняя структура генерации разрабатывается отдельным «агентом контент-завода» и здесь НЕ проектируется.

## Два вида проектов в `20_business`

- **`lion_films/`** — подряд для студии Lion Films: проекты её клиентов (megafon, sber, delicados, tbank…).
- **`ai_studio/`** — собственная AI-студия / контент-завод: внутренние проекты (`aipriest`, `cisoft`, `landing_LF_AI`, `lionfilms-ai-showreel`, `hermes_avatar`, `market_research`, эксперименты/sandbox/test).

Клиентское и своё не смешиваются.

## Модель — где что живёт

- **В `1brain` (единый корень проектов)** — всё по проекту: документы + лёгкие/средние медиа + рабочие файлы генерации. Индексируется, видно агентам.
- **Тяжёлое** (сырое видео, крупные рендеры) — на **отдельном SSD**, вне `1brain`. Из папки проекта — симлинк на SSD (по образцу существующего `Q:\Kozel podkat → /f/STORE/...`).

## Структура папки проекта

```
<client>[/<subproject>]/            # или ai_studio/<project>/
├── docs/          ← брифы, сметы, договоры, тайминги, сценарии, треатменты (текст → индексируется)
├── media/         ← визуалы (хранятся)
│   ├── references/    входящее: moodboard, чужие примеры, кв/костюм-референсы, брендбуки
│   ├── generated/     свой AI-output: избранные сген. кадры/превью/стилы
│   └── storyboards/   раскадровки, shootingboards, kadr-превью
└── production/    ← рабочие файлы из WORK (генерация, рендеры) — переносятся КАК ЕСТЬ,
                     внутренняя структура не проектируется (ведёт агент контент-завода);
                     тяжёлое → симлинк _heavy → SSD
```

`<subproject>` — только где у клиента явно >1 проекта (`sber/card`, `megafon/love`, `delicados/duo-cherepitsas`). Одиночные — плоско.

## Верхний уровень

```
20_business/
├── lion_films/
│   ├── projects/
│   │   ├── <client>[/<subproject>]/{docs,media/...,production/}
│   │   └── _unsorted/           клиент не определяется из имени
│   ├── _studio/{docs,media}/    студийное Lion Films (презентации, portfolio, лого, рилы)
│   └── contracts/               рамочные договоры (на студию/несколько проектов)
├── ai_studio/                   собственные внутренние проекты (структуру генерации не трогаем)
│   ├── <project>/               aipriest, cisoft, landing_LF_AI, showreel, hermes_avatar…
│   └── _sandbox/                эксперименты, test
├── z_nen/                       НЕ ТРОГАТЬ
└── _README.md                   НЕ ТРОГАТЬ
```

## Lifecycle (простой)

1. Приходит проект → заводится папка `lion_films/projects/<client>/` (клиентский) или `ai_studio/<project>/` (свой).
2. Документы (бриф/смета/договор) → `docs/`. Референсы → `media/references/`.
3. Работа/генерация → `production/` (агент контент-завода). Избранные финальные визуалы дублируются/оседают в `media/generated/` или `media/storyboards/`.
4. Тяжёлое сырьё/видео → SSD, симлинк из `production/_heavy`.
5. Всё по проекту — в одной папке; искать в одном месте. `WORK` как отдельная область не нужен.

## Индексация (что реально в поиске)

- **`docs/` и любой текст** (pdf/docx/doc/xls(x)/txt/md/csv/pptx/pages) → полный семантический поиск (`kf_search`, bge-m3), сущности → граф. Индексация — по расширению, не по папке.
- **Медиа** (png/jpg/jpeg/webp/mp4/mov) в `media/`, `production/` → хранятся; находятся по имени/пути/проекту. **Содержимое не читается** (нет OCR/vision/Whisper — будущая веха).

## Правила раскладки (реорганизация + впредь)

1. **Клиент/подпроект** — из имени файла (для `lion_films`); для внутренних — имя проекта в `ai_studio/`.
2. **Маркеры имени > расширение.** Порядок внутри проекта:
   - (a) `storyboard`/`shootingboard`/`raskadrovka`/`kadr` → `media/storyboards/`;
   - (b) `-ai`/`generated`/`comfy`/`sketches-ai`/`stills` → `media/generated/`;
   - (c) визуальное расширение (png/jpg/jpeg/webp/mp4/mov) → `media/references/`;
   - (d) текст (pdf/docx/doc/xls/xlsx/txt/md/csv/pptx/pages) → `docs/`.
3. **Студийное Lion Films** (презентации студии, portfolio, showreel, лого, финансы, rate-cards) → `lion_films/_studio/{docs,media}`.
4. **Договоры:** проектные → `projects/<client>/docs/`; рамочные → `lion_films/contracts/`.
5. **Клиент не определяется** → `projects/_unsorted/` + сообщить.
6. **Рабочие папки WORK-проектов** переносятся в `production/` соответствующего проекта КАК ЕСТЬ (внутренность не трогаем).
7. **Перемещать, не копировать** (`mv`). Не терять файлы. Не трогать `z_nen`, `_README.md`.

## Реализация — фазы (декомпозиция)

- **Фаза 1** — реорганизация существующих 214 документов `lion_films` → `projects/<client>/{docs,media}` + `_studio` + `contracts` + `_unsorted`. (Уже классифицировано; переработать под `docs/media`.)
- **Фаза 2** — упразднение `WORK`: клиентские production-папки → `projects/<client>/production/`; внутренние → `ai_studio/`; симлинки на SSD для тяжёлого.
- **Фаза 3 (позже)** — `kf_add_file` (Hermes кладёт присланный файл в проект + индексирует) и content-индексация медиа (OCR/Whisper/vision).
- После Фаз 1 и 2 — **переиндексация `1brain`** (`source_path` меняются; ingest подхватит новые, удалит старые; граф/векторы пересобираются).

## Не-цели / сознательно отложено

- Тяжёлое видео в `1brain` — остаётся на SSD.
- Проектирование внутренней структуры `production/` (пайплайн генерации) — ведёт отдельный агент контент-завода.
- `kf_add_file`, content-индексация медиа — Фаза 3.
- Раздел `tenders/` не создаётся; переход тендер→проект — вручную по команде пользователя.
